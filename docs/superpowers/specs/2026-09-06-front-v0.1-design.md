# Casal Conectados — Front v0.1

## Objetivo
Criar a primeira versão visual do app **Casal Conectados**, inspirada na experiência do Life360, sem login, backend ou rastreamento real nesta etapa.

## Escopo
A v0.1 será exclusivamente de front-end e servirá para validar a experiência visual mobile.

### Incluído
- mapa ocupando praticamente toda a tela principal;
- dois avatares simulados posicionados no mapa;
- identificação visual de João e da parceira;
- status mockado como “Atualizado agora”;
- painel inferior flutuante com os dois perfis;
- navegação inferior simples;
- layout responsivo priorizando smartphones;
- dados totalmente simulados/localmente definidos.

### Fora do escopo
- login;
- cadastro;
- pareamento real;
- backend;
- banco de dados;
- localização GPS real;
- rastreamento em segundo plano;
- notificações;
- histórico;
- geofencing;
- publicação nas lojas.

## Direção visual
A interface deve lembrar a estrutura geral do Life360, sem copiar identidade visual, marca, ícones proprietários ou layout pixel a pixel.

Princípios:
- mapa como elemento dominante;
- interface limpa e mobile-first;
- poucos controles visíveis por vez;
- cartões/painéis flutuantes sobre o mapa;
- boa legibilidade e hierarquia visual;
- aparência moderna e amigável para um app de casal.

## Estrutura da tela principal

### Topo
Barra superior discreta contendo o nome **Casal Conectados** e um controle visual simples para futuras ações.

### Mapa
Área principal da tela, ocupando a maior parte da viewport.

Nesta fase o mapa pode usar dados e posições simuladas. Dois marcadores com avatar representarão o casal.

### Marcadores
Cada pessoa terá:
- avatar circular;
- nome curto;
- indicação de presença/localização simulada.

### Painel inferior
Painel flutuante com resumo dos dois perfis:
- avatar;
- nome;
- status “Atualizado agora”.

### Navegação inferior
Estrutura simples preparada para futuras áreas do app. Nesta v0.1, apenas a aba principal precisa ter conteúdo funcional.

## Arquitetura inicial
- React;
- TypeScript;
- Vite;
- estrutura preparada para evolução futura para PWA/Capacitor;
- componentes pequenos e separados por responsabilidade;
- dados mockados isolados da camada visual para facilitar substituição futura por dados reais.

## Fluxo de dados
Nesta versão, os dados dos dois usuários e suas posições serão definidos localmente em mocks. A UI consumirá esses dados como se viessem de uma API, para evitar acoplamento desnecessário quando o backend for criado.

## Estados e erros
Como não haverá backend, os únicos estados necessários serão:
- estado normal com mapa e dois usuários;
- fallback visual caso o mapa não carregue;
- layout funcional mesmo sem dados externos.

## Testes e validação
A v0.1 deverá ser validada com:
- build de produção;
- verificação de TypeScript;
- renderização mobile responsiva;
- ausência de erros no console durante o fluxo principal;
- confirmação de que o mapa, os avatares, o painel inferior e a navegação aparecem corretamente.

## Critério de conclusão
A etapa estará concluída quando existir uma tela mobile utilizável que represente visualmente o conceito do **Casal Conectados**, com mapa dominante, os dois perfis simulados e navegação básica, sem qualquer dependência de autenticação ou backend.
